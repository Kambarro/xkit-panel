## 🎯 Что это

**XKIT Panel** превращает чистый VPS (Ubuntu 24.04+) в готовый VPN-сервер и берёт на себя всё обслуживание — **без 3X-UI, без TUI, без терминала**:

- ставит **Xray-core + собственную лёгкую Go-панель** и прячет её за **nginx** — снаружи панель не видна, на «случайный» заход сервер отвечает обычным сайтом-прикрытием;
- настраивает **TLS-сертификат** (домен или IP) и маскировку по умолчанию;
- создаёт **протоколы**: VLESS REALITY / XHTTP / WS, AmneziaWG 3.1, Hysteria 2, Trojan, VMess, Shadowsocks 2022;
- **один пользователь = все протоколы = одна подписка** с общим лимитом и сроком;
- управляет всем через **веб-браузер** (ПК и телефон) или **Telegram-бота**;
- подключает **зарубежные ноды** и распределяет трафик: клиент → ваш сервер → каскад → мир;
- **сам выбирает лучшую ноду** для клиента и переживает отвал без обрыва сессий;
- делает **бэкапы** и переносит сервер на новую машину.

> Это преемник [XKIT](https://github.com/kambarro/xkit) (Bash + 3X-UI + TUI). Панель заменяет слой 3X-UI собственной Go-панелью, переиспользуя идеи каскада, маскировки и подписок — но добавляет sticky-балансировщик, выбор страны, группы протоколов и горячую маршрутизацию без рестартов.

## 💡 Философия

- **Для домохозяйки.** Поднять VPN, добавить человека, выдать подписку — мышкой, без терминала. Терминал нужен только для установки и аварийного восстановления.
- **Снаружи — только нужное.** Панель слушает `127.0.0.1`. Всё, что можно спрятать за 443 — спрятано **по умолчанию, без возможности изменить**: снаружи один TCP-порт, трафик неотличим от HTTPS вашего домена. Что спрятать нельзя (UDP, xhttp/trojan) — честно помечено и предупреждает.
- **Один пользователь — одна подписка.** Добавили человека — он сразу во всех протоколах. Добавили протокол — он сам попадёт в подписки (auto_add). Никакой ручной синхронизации.
- **Панель — мозг, Xray — мышцы.** Control plane (SQLite + балансировщик) отдельно от data plane (Xray). Маршрутизация меняется **горячо через gRPC** — без рестартов и обрыва чужих сессий.
- **Ошибка = откат.** Конфиг туннеля применяется к обоим концам атомарно, при провале — откат. Перед удалением — очистка всех связанных сущностей.
- **Чужое не трогаем.** Панель не включает ваш файрвол молча: сначала добавляет allow-правила, синхронизация — по кнопке.
- **Секреты не утекают.** QR и подписки генерируются локально (go-qrcode), без внешних сервисов. Пароли — argon2id, сессии переживают рестарт.

## ⚡ Быстрый старт

### Что понадобится

- VPS с **Ubuntu 24.04+**, доступ `root` по SSH;
- архитектура `amd64` или `arm64`;
- домен **не обязателен** — работает и по IP (но с доменом маскировка естественнее).

### Установка

```bash
curl -fsSL https://raw.githubusercontent.com/kambarro/xkit-panel/main/install.sh | bash
```

Установщик спросит **только домен** (или Enter для IP). Остальное — дефолты. Автоматически поднимется Xray, панель, nginx с сайтом-прикрытием, TLS и маскировка. В конце выдаст **адрес панели, логин и пароль**.

Дальше — всё в браузере. Откройте адрес, войдите, мастер настройки предложит выбрать протоколы и проверит сервер.

### Перенос сервера из бэкапа

```bash
xkit-panel restore [архив.tar.gz]   # без аргумента — последний бэкап
```

Восстанавливает клиентов, ноды, настройки и TLS-ключи. Ноды переподключаются, клиенты сохраняют свои подписки. В каждом бэкапе лежит `RESTORE.txt` с пошаговой инструкцией.

## 🛡️ Протоколы

Экран **«Протоколы»** — каждый протокол это карточка с переключателем, портом и правкой.

| Протокол | Что это | Когда выбирать |
|---|---|---|
| **VLESS + REALITY + Vision** | основной TCP-профиль :443, маскировка под чужой TLS-сайт | базовый вариант, работает у большинства |
| **VLESS + XHTTP + REALITY** | альтернативный транспорт | если обычный REALITY прижимают |
| **VLESS + WS + TLS** | WebSocket транспорт | обход через CDN / стандартные порты |
| **AmneziaWG 3.1** | обфусцированный WireGuard (Header Protection) | UDP там, где TCP режут; роутеры, AmneziaVPN |
| **Hysteria 2** | быстрый UDP/QUIC с маскировкой | плохие каналы, мобильные сети |
| **Trojan + TLS** | классический Trojan | совместимость |
| **VMess + WS** | VMess транспорт | совместимость |
| **Shadowsocks 2022** | SS2022 (blake3-aes-128-gcm) | лёгкий UDP/TCP |

Что важно знать:

- **Пользователь создаётся сразу во все протоколы** — одна подписка на всё;
- **Выключить ≠ удалить**: протокол можно выключить — он пропадёт из подписок и закроет порт, но останется в панели; включили обратно — вернулся;
- **Добавили протокол позже?** Флаг `auto_add` сам добавит его во все группы и подписки;
- **Группы и override**: можно создать группу (например «Роутеры» — только REALITY + AWG) и назначить её клиентам, либо задать набор протоколов **персонально** каждому. Запрет — настоящий: клиент удаляется из inbound запрещённого протокола, а не просто «не видит ссылку»;
- **AmneziaWG — соло-выход с мастера**: AWG-клиенты выходят в интернет напрямую с IP мастера (каскад мастер→нода работает для xray-протоколов, не для AWG). Нужен выход через ноду — используйте REALITY / XHTTP / WS / Hysteria2. IPv6 в AWG-конфиге отключён (серверы работают по IPv4);
- REALITY-мастер сам **сканирует и предлагает сайты-прикрытия** (кнопка «использовать»);
- при выборе протокола панель **подсказывает нагрузку** на систему (RAM/CPU) — лишнее не включайте.

### 🎭 Маскировка по умолчанию

Панель честно показывает уровень маскировки каждого протокола (бейдж на карточке):

| Бейдж | Что значит | Протоколы |
|---|---|---|
| 🟢 **за 443** | клиент всегда подключается к `домен:443`, трафик неотличим от сайта; внутренний порт — косметика, менять нельзя | VLESS REALITY, VLESS-WS, VMess-WS |
| 🟠 **UDP** | отдельный транспорт, за TCP-443 не спрятать; маскировка обфускацией (salamander / AWG Header Protection) | AmneziaWG (:443/udp), Hysteria2 (:8443/udp) |
| 🔴 **свой порт** | виден провайдеру, спрятать за 443 нельзя — предупреждаем честно | XHTTP, Trojan, SS2022 |

Цепочка для 🟢: `клиент :443 → REALITY → TLS-dispatcher (ваш LE-сертификат) → fallback по path → внутренний inbound`. Снаружи открыт **один TCP-порт**.

> Локальный статус «работает» не гарантирует проходимость у конкретного провайдера клиента — это зависит от сети, региона и репутации IP. Проверяйте реальным подключением.

## ⚖️ Балансировщик и ноды

Главное отличие от XKIT: **собственный sticky-балансировщик** в панели (Xray = чистый data plane).

```text
Клиент → Мастер (один адрес, REALITY :443, маскировка)
           │  per-user routing (gRPC, горячо)
           ├─ ivan → нода NL-1 (приоритет 1)
           ├─ petra → нода NL-1
           └─ john → нода NL-2 (приоритет 2)
                     │
                     └─ freedom exit (IP ноды = страна)
```

- **Sticky**: клиент закреплён за нодой, не скачет между соединениями;
- **Приоритет + цена + загрузка**: лучшая нода страны для клиента;
- **Failover** только при реальном отвале (N=3 проб, гистерезис), внутри страны; все ноды страны мертвы → fallback на другую страну;
- **Re-evaluate**: при переподключении клиент снова на лучшей ноде;
- **Без форка Xray, без рестартов, без обрыва чужих сессий** (gRPC hot-reload);
- **Страна выхода**: клиент выбирает страну на странице подписки или кнопкой «🌍 Страна» в TG-боте — один UUID и одна ссылка на протокол, адрес мастера один, маскировка идеальна. Смена горячая (не чаще раза в 10 секунд), старые страновые ссылки продолжают работать через базовое правило.

### 🧭 Режимы маршрутизации

Три режима (Настройки, expert):

- **solo** — всё напрямую с мастера (нод нет);
- **ru-direct** — российские домены/IP напрямую, остальное через ноды;
- **antifilter** — через ноды только **заблокированное** (точные списки RunetFreedom, обновление каждые 30 мин с кешем и fallback), остальное напрямую с мастера — минимальная нагрузка на ноды.

Поверх режима — **always-правила**: категории (telegram, google, netflix, нейросети…) и свои домены, которые всегда идут через ноду (или всегда напрямую). Конфликт direct∩proxy подсвечивается, direct приоритетнее. Expert-флаг `/24-margin` расширяет IP-список до подсетей /24 (охват с запасом). Заблокированный трафик идёт на «свою» ноду клиента без скачков (sticky).

### 📊 Трафик по периодам

У клиента и ноды — суммарный трафик за всё время (lifetime) и скользящие окна **24ч / 7д / 30д** (почасовые бакеты, хранение 90 дней). Селект периода в шапке таблиц, тултип с разбивкой up/down. Переживает рестарты ядра, не задваивается.

### Ноды

Экран **«Ноды»** — добавление по SSH (панель сама ставит Xray + nginx camo на ноде), и для каждой ноды:

- **проверка** (10 пунктов: SSH / Xray / порт / конфиг / nginx / UFW / агент / диск / NTP / туннель);
- **тест туннеля** (TLS handshake);
- **метрики агента**: CPU / RAM / диск / сеть изнутри ноды;
- **качество**: score / uptime / задержка, графики за 1ч–30д;
- **транспорт мастер→нода**: XHTTP / TCP / WS + REALITY или Hysteria2 — переключение с проверкой и откатом;
- **AWG-каскад**: AmneziaWG-туннель мастер→нода (SOCKS-outbound), переживает рестарт панели; используется xray-протоколами — клиенты самого AWG выходят с мастера (соло);
- **поля туннеля**: порт / SNI / path / REALITY-ключи — правка **обоих концов атомарно**;
- **MTU туннеля** (оба конца) + авто-подбор;
- **биллинг**: лимит GB, день сброса, множитель трафика хостера;
- **версии** Xray / агента + обновление;
- **вкл/выкл / reboot / удаление**, capacity (вес);
- **настройки ноды**: переименовать, сменить страну, приоритет/цена, **дата истечения аренды**, **заметка** (хостер/тариф/контакт);
- **аренда**: бот напоминает за 7/3/1 день до истечения; нода НЕ отключается автоматически (только уведомление);
- **версии Xray/агента**: стабильные релизы отдельно, бета/пре-релизы свёрнуты с предупреждением; обновление прямо из UI.

## 🔗 Подписки

Каждый пользователь получает **страницу подписки** (открыть в браузере):

- **QR-коды** и ссылки для v2rayNG / Streisand / Hiddify / v2rayN (base64);
- **Clash / Mihomo YAML** — с раздельной маршрутизацией: RU-сайты напрямую, остальное через прокси;
- **sing-box JSON** и **xray-json** (incy);
- **`/amnezia`** — страница с QR и конфигом для AmneziaVPN (vpn:// + .conf);
- **селектор страны** выхода;
- **редактор маршрутизации** (если разрешён админом);
- **Happ crypto-link** (`happ://crypt3`) — скрывает адрес подписки от пользователя.

Формат определяется автоматически по User-Agent клиента. QR генерируется локально.

Дополнительно per-client: **срок + квота + автопродление**, **HWID-лимит устройств** (с отвязкой), **MTU** (течёт в подписку/conf/QR), **claim-link** для привязки Telegram.

## 🤖 Telegram-бот

Управление с телефона:

```text
Настройки → Telegram-бот → токен + ваш чат
```

Меню бота:

- **👥 Пользователи** — создать (пошагово: email → дни → GB), список, подписка и QR, удалить (с подтверждением);
- **🖥 Ноды** — состояние и список;
- **📊 Статус** — клиенты, ноды, мастер.

**Claim-привязка**: админ генерирует одноразовую ссылку `t.me/<bot>?start=<token>` — клиент открывает, его чат привязывается к учётке, приходят уведомления о сроке и квоте. Доступ — только у admin-чатов.

**Бот работает даже там, где Telegram заблокирован**: если прямой доступ к Telegram API недоступен, панель автоматически поднимает SSH-туннель через зарубежную ноду (SOCKS5) и доставляет сообщения через неё. Канал проверяется каждые ~20с и восстанавливается сам; при возврате прямого доступа — переключается обратно. Статус канала виден в настройках (`↗ direct` / `⇄ нода`). Кнопка ↻ перезапускает бота.

**Напоминания**: бот шлёт админу об истечении аренды нод (за 7/3/1 день) и об отключении ноды; клиентам — о сроке подписки и квоте.

## 🩺 Доктор

Встроенная диагностика: кнопка «Проверить» на дашборде проверяет **13 пунктов мастера + ноды через агент**:

- Сертификат TLS (срок, автопродление)
- Camo-сайт (отдаёт 200)
- Xray / Nginx / Fail2ban (живы)
- REALITY-якорь :443 (включён)
- Подписки (endpoint отвечает)
- BBR / UFW / GeoIP-файлы / диск / бэкап

Каждый пункт: ✓ зелёный / ⚠ жёлтый / ✗ красный + кнопка **«Исправить»** (per-item, не «всё сразу»). Не удалось починить → **«Отчёт для комьюнити»** — JSON с версиями, логами, routing, inbounds (без паролей/ключей/клиентов). Приложите к issue — разберёмся.

## 🎭 Camo-генератор

Сайт-прикрытие генерируется автоматически при установке: **22 категории** (14 SaaS + 8 игровых серверов: Minecraft, Lineage 2, Rust, CS2, ARK, FiveM, Terraria, Valheim). Каждый seed → уникальный бренд, палитра, layout, контент. Сотни комбинаций — два сервера рядом никогда не выглядят одинаково.

- Если есть домен → бренд из домена (example.com → «Example»), без рассинхрона
- Ноды получают лёгкую вариацию того же бренда (один кластер = один проект)
- Живые анимации: счётчики, fade-in, online-pulse
- Кнопка «Сгенерировать новый сайт» или загрузка своего ZIP

## 🔐 Подписанные релизы

Бинари в [Releases](https://github.com/kambarro/xkit-panel/releases) подписаны **Ed25519 (SSH signatures)**:

```bash
# Проверка подписи
ssh-keygen -Y verify -f allowed_signers -I xkit-release -n xkit-release \
  -s SHA256SUMS.sig < SHA256SUMS
```

Публичный ключ: [`assets/release.pub`](assets/release.pub). Файл `allowed_signers` в релизе. Подпись покрывает SHA256-суммы всех бинарей — любая подмена обнаруживается.

## ❓ FAQ

**Нужен ли домен?** Нет, можно по IP. Но со своим доменом маскировка естественнее.

**Чем отличается от XKIT?** XKIT — Bash + 3X-UI + TUI. Панель — собственная Go-панель поверх Xray-core: sticky-балансировщик, выбор страны, группы протоколов, горячая маршрутизация без рестартов, всё в браузере. 3X-UI не нужен.

**Клиент не подключается — что делать?** Запустите Доктор на дашборде (проверит ноды и туннели). Если сервер в порядке — дело в сети клиента/провайдере: попробуйте другой протокол (UDP-варианты часто живут там, где режут TCP) или другую страну.

**Telegram заблокирован на сервере — бот будет работать?** Да. Панель автоматически поднимает SSH-туннель через зарубежную ноду и доставляет сообщения через неё (SOCKS5). Канал восстанавливается сам, статус виден в настройках. Нужна хотя бы одна живая нода.

**Гарантирует ли панель обход блокировок?** Нет. Инструмент настраивает сервер; проходимость зависит от сети, региона и времени. Никаких гарантий.
